# Diagram 4: one frame on core 1

Sources: `apps/watch/remote/src/main.c` (render_box, render_bands,
wait_te, main loop), `remote/src/qspi_fast.c`, docs/data/traces/*.html.

Draw a horizontal timeline of one 16.7 ms frame, top to bottom lanes:

**Lane 1 – the panel**: a TE (tearing effect) pulse at the start of every
60 Hz refresh. Core 1 polls GPIO13 and starts the frame on the rising edge,
so what it sends lands during the refresh: no tearing, steady cadence.

**Lane 2 – core 1 CPU**, as blocks in order:
1. "mark dirty": the second hand's old and new positions, any hand whose
   angle changed, the date, the bezel if turned -> a list of dirty **bands**
   (8 rows tall, only as wide as needed), typically 10-35 per frame.
2. For each band, `render_box` composes it row by row into a 7.5 KB buffer in
   internal RAM, in stages: (a) dial background copy from flash (or the date
   window), skipped under the bezel; (b) bezel ring via the polar lookup
   (index -> strip in RAM, plain copy); (c) hour/minute/GMT hands as vector
   shapes, only across the x-span where the row crosses a hand's footprint;
   (d) the second hand with analytic anti-aliasing (disc coverage from the
   squared distance, no sqrt) and its shadow, skipped in bands it cannot
   reach; (e) byte-swap to the panel's big-endian RGB565.
3. The box is handed to the SPI, and the CPU moves to the **next band using
   the other buffer** (double buffering). If the previous DMA is still
   running when the next box is ready, the CPU stalls (red).
4. Bezel repaint, if it turned (whole ring, 65k px, ~14 ms - the one thing
   that still exceeds a frame).
5. Stats, trace flush, wait for the next TE.

**Lane 3 – SPI2 + GDMA**: for each box three short hardware transactions:
CASET, RASET (command + address phases generated by the SPI peripheral,
~1 us each), then RAMWR with the pixels by DMA on four lines at 80 MHz
(40 MB/s: a 100x8 box takes ~40 us). Overlaps lane 2.

**Numbers on the diagram** (typical GMT face): frame work 9-13 ms of 16.7;
background ~0.5-1 ms, ring 1.3 ms, hands 4-9 ms, second hand ~4.5 ms, byte
swap 0.6 ms, SPI writes 0.5 ms (mostly hidden behind compositing); 59-60 fps.

**Callout boxes** (the history, for the article): LVGL 12-26 fps -> own
compositor 4-10 fps -> per-row stages 107 cycles/px (from 315) -> vector hands
59 fps -> direct SPI 3.4 ms -> 0.5 ms -> bezel lookup 37 -> 14 ms.

Colours: TE lavender, compose pink, stall red, bezel yellow, DMA blue (same as
the trace viewer, so the diagram and the live trace match).
